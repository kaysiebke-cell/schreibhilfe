Ein systemnäheres Layout für die Schreibhilfe

Links steht die App, wie sie heute aussieht — nachgebaut aus online/css/style.css. Rechts derselbe Bildschirm mit kühleren Flächen, Systemschrift und den Formen, die Android und iOS heute selbst benutzen. Der Aufbau bleibt in beiden Fassungen gleich: eine Ebene, ein Hauptknopf, alles in Daumenreichweite.

Was sich ändert

Nichts davon betrifft den Ablauf. Es geht um Form, Abstand und Farbe — und darum, dass es dafür künftig ein Regelwerk gibt statt zwei gewachsener nebeneinander.

Was bleibt

Der Aufbau

Kopf, Schreibfeld, Leiste. Einstellungen als eigener Bildschirm, nicht als Fenster im Fenster — die Zurück-Taste tut weiter, was man erwartet.

Ein Hauptknopf

„Korrigieren" bleibt der eine große Knopf, und was danach zu tun ist, erscheint erst danach. Der Entwurf macht ihn runder, nicht kleiner.

Daumenreichweite

  • Jede Trefferfläche mindestens 48 px
  • Alles Wichtige unten, nicht oben rechts
  • env(safe-area-inset-bottom) bleibt

Der Zwilling hinterm Feld

Der Streifen hinter dem Wort, an dem gerade geschrieben wird, funktioniert unverändert — er bekommt nur eine kühlere Farbe.

Was beim Umbau nebenbei wegfällt

Beim Nachbauen ist aufgefallen, dass in style.css Regeln stehen, zu denen es im HTML und im JavaScript nichts mehr gibt. Die brauchen im neuen Regelwerk keine Entsprechung:

  • .ki-reihe — null Treffer in index.html und app.js
  • .leiste__rechts — null Treffer
  • .baunummer — null Treffer
  • .aktionen — null Treffer
  • .btn--breit, .btn--icon — null Treffer
  • .leiste — zweimal definiert (Zeile 255 als Reihe, Zeile 407 als Spalte, die die erste wieder aufhebt)

Beide Rahmen sind Nachbauten in reinem HTML und CSS — kein Code der App läuft hier. Die Werte der linken Spalte stammen aus online/css/style.css, damit der Vergleich ehrlich ist. Die Seite liegt unter entwurf/layout-entwurf.html und wird von GitHub Pages nicht ausgeliefert — der Ablauf veröffentlicht nur online/.
